Establishing connections

In R the DBI package is important package that provides a consistent interface for connecting to and interacting with databases. It serves as a foundational layer for working with databases in R. It’s used by higher-level packages like dplyr and dbplyr to connect to databases and perform SQL operations.

# Connect to a PostgreSQL database
con <- dbConnect(RPostgres::Postgres(), 
                 dbname = "db_1",
                 host = "localhost",
                 port = 5432,
                 user = "postgres",
                 password = "password0134!")

# Execute a SQL query
query <- "SELECT * FROM student"
result <- dbGetQuery(con, query)

Selecting data

Of course, you can also run more complex raw SQL queries:

result <- dbGetQuery(con, "SELECT * FROM course_codes WHERE course_desc LIKE 'A%'")

result

If you need to fetch results one at a time you might want to use dbFetch()

query <- dbSendQuery(con, "SELECT * FROM course_codes WHERE course_desc LIKE 'A%'")
result <- dbFetch(query, n = 1)
result

The dbplyr package allows you to write R code that gets translated into SQL queries, similarly to what SQLAlchemy does in Python. It is an extension of the dplyr package specifically designed to work with databases. On future weeks we are going to see many dplyr methods to manipulate data. Since there is no much difference between the syntax of dbplyrand dplyr, this won’t be covered in depth now, but you can see some examples of queries employing dbplyr methods below: tbl = table

library(dplyr)
library(dbplyr)

# Create a remote data table using dbplyr
remote_table <- tbl(con, "student")

Show table names

In R there is no need to reflect tables. You can use for example dbListTables passing the connection object to list all tables in the dataset.

# Build a vector of table names: tables
tables <- dbListTables(con)

# Display structure of tables
str(tables)
 chr [1:4] "course_codes" "dept" "emp" "student"

You can also import all tables using lapply

# Import all tables
tables <- lapply(tables, dbReadTable, conn = con)

Extract ERD

Unfortunately in R there is no easy way to extract the ERD of a generic database.
